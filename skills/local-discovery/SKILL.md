# Discovery

## What this skill does

This skill routes a discovery problem to the right engines, runs them in order, and turns the result into an invention. You name the problem in plain words. You pick a phase. You pick the engines that fit that phase. You run each engine and record what it hands on. You end with an invention.

This skill ties 16 engines together. Invention is the outcome step of this skill. Invention is not a separate engine. Invention is not a 17th skill.

The skill runs in 4 phases.

- Research: find what is true and what is still unknown.
- Proof: test a claim with a check that can fail.
- Stuck: change the frame when forward work has failed.
- Search: map the options and test the best ones first.

The Core 4 loop drives most work. The loop runs Anomaly to Abduction to Falsification, with First Principles underneath. Anomaly finds where reality breaks the model. Abduction offers the best cause for that break. Falsification tests that cause with a check that can fail. First Principles holds the loop to what must be true, not to what is merely usual.

The 16 engines, each with its one-line trigger:

- Anomaly Hunting: use it when what you see breaks what you expected.
- Abduction: use it when you need the best cause for a surprise.
- Falsification: use it when you need a check that can prove a claim wrong.
- First Principles: use it when you need to rebuild from what must be true.
- Induction: use it when a pattern across cases points to a wider rule.
- Deduction: use it when a rule should predict one clear result.
- Analysis and Synthesis: use it when you need to split a thing apart, then rebuild it as a whole.
- Thought Experiments: use it when you need to test an idea in your head before you test it in the world.
- Analogy and Cross-Domain Transfer: use it when a fix from another field may fit this problem.
- Inversion: use it when forward work has failed, so work back from the failure.
- Counterfactual Thinking: use it when you need to ask what would change if one fact were different.
- Constraint-Based Discovery: use it when a hard limit shapes what can work.
- Search the Possibility Space: use it when you need to map the options before you pick one.
- Evolutionary Search: use it when small changes, kept or dropped by test, can find a better form.
- Serendipity + Prepared Mind: use it when a chance find meets a mind ready to see its use.
- Consilience: use it when separate lines of proof point to the same answer.

## Input

Bring these four items before you start.

- Problem: the problem in plain words, in one or two sentences.
- Model: what you now believe, in one or two sentences.
- Observations: what you saw, with numbers where you have them, and the source for each one.
- Goal: what a good result would look like, in plain words.

If you have no model, state one first. If you have no observations, gather some first. Do not start the loop on a guess alone.

## Guard: light check or full use

Pick one before you start. Judge by impact plus reversibility. Do not judge by reversibility alone. A step can be easy to reverse and still cost time, money, or trust.

- Light check. Use this for a routine problem with low impact and easy reversal. Run Step 1, Step 2, and Step 3 only, then run one engine and stop, or stop if no engine fits.
- Full use. Use this for a new problem, a costly move, a claim that shapes the next step, or any problem with high impact or that is hard to reverse. Run all steps.

Ask these three questions to pick.

- Is there a decision to make, with an action that follows it?
- Could the current model be wrong in a way that costs time, money, or trust?
- Would a new finding change what I do next?

If no decision follows, answer directly. If the problem is low impact and easy to reverse, use the light check. If the problem is high impact or hard to reverse, use full use.

## Steps in order

Work the steps in order. Write each result down before you move on. Do not skip Step 1. Without a plain-word problem, every engine pulls in a different direction.

### Step 1: Name the problem in plain words

Write the problem in one or two sentences. Use plain words. Name the thing that fails, the place it fails, and the size of the failure where you have a number. Do not invent a number. If no number exists, say so.

Write the model next, in one or two sentences. Write what you expect to see if the model is right. Write what you saw instead, with the source and the number for each observation.

### Step 2: Pick the phase

Pick one phase to start.

- Pick Research when you need to learn what is true first.
- Pick Proof when you have a claim and need a check that can fail.
- Pick Stuck when forward work has failed and you need a new frame.
- Pick Search when you have a bounded set of options and need to test them.

Record the phase and the reason for it in one line. You may move to another phase later. Record each move and its reason.

### Step 3: Pick the engine or engines in order

Pick the engine or engines that fit the phase and the problem. Pick them in the order you will run them. Name each engine and give a one-line reason for it.

Start with the Core 4 loop when the problem fits it. Run Anomaly Hunting first. Run Abduction second. Run Falsification third. Hold First Principles underneath the whole loop. Use the other engines when the phase calls for them. Use Inversion first when you are in the Stuck phase. Use Search the Possibility Space when you are in the Search phase.

Do not pick more than 3 engines for one pass. If the problem needs more, finish one pass first, then start a new pass.

### Step 4: Run each engine and record its handoff

Run each engine in the order you picked. Follow that engine's own steps. Record what each engine hands on before you start the next one. A handoff holds the finding, the source or number behind it, and the next question it raises.

Do not carry a guessed cause forward as a fact. A guess from one engine is a claim for the next engine to test. If an engine finds nothing, record that too. A null result is a result.

If an engine contradicts an earlier engine, stop and name the clash. Do not smooth it over. The clash is the next thing to test.

### Step 5: Invention

End with an Invention step. State what new thing the discovery makes possible. Name the thing in plain words. Say who would use it and what it would let them do that they cannot do now.

State what test would prove it. Name the check, the number it must hit, and the result that would prove the invention wrong. An invention with no test is a wish, not a result.

Record the invention, the test, and the limits of what you know. Name at least one limit. If the invention needs a check you cannot run yet, say so.

## Stop rule

Set the limit before you start. The maximum is 3 engines per pass and 2 passes per problem. Stop when you reach the limit. Then write the invention from what you have, or stop if no finding survived.

Stop early if no engine fits the problem. Stop early if every engine returns a null result. Stop early if the invention test cannot be stated. Do not keep adding engines to get around the limit. Do not spend more time on the problem than the decision is worth.

If the budget runs out in the middle of a pass, mark the unrun engines as unrun. Reduce the scope to what you did run. Do not claim an unrun engine as done.

## When this skill does not apply

Do not use this skill when there is no problem to solve. If you only want a fact, look the fact up.

Do not use this skill when the answer is a known procedure. Follow the procedure instead.

Do not use this skill when you have no model and no observations. State a model and gather observations first, or use a different skill.

Do not use this skill to dress up a guess as a discovery. A discovery needs an observation, a test, and an invention with its own test.

## Worked example: the coffee cart that loses sales on rainy days

Problem: a coffee cart sells 40 cups on a dry morning and 18 cups on a rainy morning. The owner believes weather does not change sales. The cart has no cover, and the queue stands in the rain.

Model: weather does not change sales. The cart should sell about 40 cups each morning, rain or shine.

Observations, from the sales log for the last four weeks: dry mornings sold 38 to 43 cups. Rainy mornings sold 15 to 20 cups. Source: the sales log, dates and cup counts as listed.

Phase: Research first, then Proof. The gap is clear, but the cause is not yet proven.

Engines in order, with reasons:

- Anomaly Hunting first, because rainy sales break the model by more than half.
- Abduction second, because the break needs a best cause, and the open queue in the rain is the plainest one.
- Falsification third, because the cause needs a check that can fail.

Run each engine and record its handoff.

Anomaly Hunting: the mismatch is rainy mornings at 15 to 20 cups against a predicted 40 cups. The gap is 20 to 25 cups. Scores: surprise 4, importance 4, checkability 5. The log covers all mornings, so the pattern is not a cherry-picked case. Handoff: rainy sales break the model, and the gap is large and testable.

Abduction: the best cause is that buyers skip the queue when it stands in the rain. The cart has no cover. No other cause fits as plainly, because dry mornings with the same menu and price sell 40 cups. Handoff: the open queue in the rain drives buyers away.

Falsification: the check is to add a cover for one rainy week and count cups. The claim fails if rainy sales stay at 15 to 20 cups with the cover in place. The claim holds if rainy sales rise toward 35 cups or more. The test ran for one rainy week. Rainy sales with the cover were 34 to 38 cups. The cause survived its check.

Invention: a clip-on rain cover with a dry queue lane, built for small carts. It lets a cart keep its dry-morning sales on rainy mornings. The test that would prove it is a two-week trial on three carts: rainy sales must stay within 5 cups of dry sales, or the invention fails. Limit: the trial covered one cart and one week, so three carts and two weeks would firm the claim.

## Commands

- "show phases" lists the 4 phases with a one-line use for each.
- "show engines" lists all 16 engines with a one-line trigger for each.
- "show route" emits the phase, the engines in order, and the reason for each.
- "show handoffs" emits the handoff record from each engine run.
- "show invention" emits the invention, its test, and its limits.
- "save state" emits the route, the handoffs, and the invention together.
- "resume from:" restores a saved route and continues from the next unrun engine.
